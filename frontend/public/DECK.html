The Model

Explained the way you'd explain it to your parents.

📄

Google Forms

Data arrives in a clear plastic bag, dropped in an unlocked drawer. Anyone walking past can read it.

✉️🔒

SCB Platform

Each registration is a sealed envelope. The phone seals it before posting. Stored in a vault. Only authorized operators have a key. Opening leaves a trace. Envelopes auto-shred after 90 days.

How it works

AES-256-GCM. Same as US top-secret.

  • AES-256-GCM — the same standard the US government uses for top-secret classified data. Banks use it. WhatsApp uses it. Public algorithm, no known break in 20+ years.
  • Browser-side encryption — the volunteer's phone encrypts the data using the browser's built-in Web Crypto API. No third-party library. No CDN. No supply-chain risk.
  • Per-record IV — every registration gets a fresh 96-bit random initialization vector. Same name, encrypted twice, produces totally different ciphertext.
  • One-way dedupe hash — duplicate detection works via SHA-256(eventId + employeeId). Irreversible. We can detect duplicates without ever storing the ID.

What's not perfect — yet.

Three known gaps

  • AES key in JS bundle. A phished operator + devtools = full decrypt. Fix: Phase B Secret Manager + Cloud Function. ~1 week.
  • 2FA not enforced on operator accounts. Fix: flip Firebase Auth setting. ~1 hour.
  • Auto-delete index pending console click. Fix: one button in Firebase Console.

None of these exist on Google Forms either.

Google Forms doesn't attempt encryption at all. The question on this platform isn't "is it perfect today" — it's "is it on a credible path to bank-grade."

Code is open. Plan is written. Trajectory is real.
